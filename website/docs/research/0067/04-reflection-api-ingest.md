# 04. Reflection API ingest

This note covers the `ReflectTool.java` implementation in detail: how it loads a JAR, what reflection APIs it calls, what information it recovers, and what it emits.

## Overview

`ReflectTool` is a self-contained Java program (~400 LOC) compiled to `reflect-tool.jar` and bundled inside the `mochi` Go binary as an embedded resource (`//go:embed pkg/pkgjava/reflect/reflect-tool.jar`). When `mochi pkg lock` processes a Java dependency, it:

1. Materialises `reflect-tool.jar` to a temp directory (once per process).
2. Invokes `java -jar <path>/reflect-tool.jar <jar-path> --classpath <transitive-classpath>` as a subprocess.
3. Reads the JSON surface document from stdout.
4. Parses the JSON into a `pkgjava.Surface` Go struct.

The Java subprocess approach (rather than calling the reflection API via JNI from Go) has two advantages: it uses whatever `java` binary is on PATH, which may be a newer JDK than what `JNI_CreateJavaVM` would embed; and it avoids the JNI startup cost for the lock step (the lock step may run offline or in a CI environment where we do not want to spin up the embedded JVM).

## URLClassLoader setup

ReflectTool loads the target JAR and its transitive dependencies via `URLClassLoader`:

```java
public static URLClassLoader buildClassLoader(String jarPath, String[] classpathEntries) {
    URL[] urls = new URL[classpathEntries.length + 1];
    urls[0] = new File(jarPath).toURI().toURL();
    for (int i = 0; i < classpathEntries.length; i++) {
        urls[i + 1] = new File(classpathEntries[i]).toURI().toURL();
    }
    // Parent is the bootstrap classloader (null), not the system classloader.
    // This prevents classes from the tool itself from leaking into the target JAR's class space.
    return new URLClassLoader(urls, null);
}
```

The classpath entries (provided via `--classpath <jar1>:<jar2>:...`) are the transitive dependencies of the target JAR. Without them, reflection on classes that reference transitive types (e.g., `guava` references `failureaccess`) would throw `ClassNotFoundException` when trying to resolve return types or parameter types of the reflected methods.

## Walking classes in the JAR

ReflectTool enumerates classes by walking the JAR's entries directly:

```java
public static List<String> findClassNames(String jarPath) throws IOException {
    List<String> names = new ArrayList<>();
    try (JarFile jar = new JarFile(jarPath)) {
        Enumeration<JarEntry> entries = jar.entries();
        while (entries.hasMoreElements()) {
            JarEntry entry = entries.nextElement();
            String name = entry.getName();
            if (name.endsWith(".class") && !name.equals("module-info.class")) {
                // Convert "com/example/Foo.class" to "com.example.Foo"
                String className = name.replace('/', '.').substring(0, name.length() - 6);
                names.add(className);
            }
        }
    }
    return names;
}
```

For each class name, ReflectTool calls `classLoader.loadClass(className)` to get the `Class<?>` object. Classes that fail to load (due to missing transitive deps not in the provided classpath, or due to `ExceptionInInitializerError` from static initializers that have side effects) are recorded in a `load_errors` list in the JSON output and skipped.

## getDeclaredMethods and visibility filtering

```java
public static List<MethodInfo> extractMethods(Class<?> clazz) {
    List<MethodInfo> methods = new ArrayList<>();
    for (Method m : clazz.getDeclaredMethods()) {
        int mod = m.getModifiers();
        // Only expose public and protected methods
        if (!Modifier.isPublic(mod) && !Modifier.isProtected(mod)) continue;
        // Skip synthetic methods (bridge methods generated by the compiler for generics)
        if (m.isSynthetic()) continue;
        // Skip deprecated methods only if --skip-deprecated is set
        methods.add(buildMethodInfo(m));
    }
    return methods;
}
```

Bridge methods: the Java compiler generates bridge methods for generic type compatibility (e.g., a `List<String>` implementation generates a `List.get(int) -> Object` bridge method alongside the `List<String>.get(int) -> String` typed method). ReflectTool skips synthetic methods to avoid exposing these compiler-generated duplicates.

## Generic type recovery via getGenericParameterTypes

Java generics are erased at the bytecode level (e.g., `List<String>` becomes `List`), but the compiler writes the generic signature into the `Signature` bytecode attribute. The reflection API surfaces this via `getGenericParameterTypes()` and `getGenericReturnType()`:

```java
private static String typeToString(Type type) {
    if (type instanceof Class<?> clazz) {
        return clazz.getName();
    } else if (type instanceof ParameterizedType pt) {
        // e.g., List<String> -> "java.util.List<java.lang.String>"
        String raw = typeToString(pt.getRawType());
        Type[] args = pt.getActualTypeArguments();
        String argStr = Arrays.stream(args).map(ReflectTool::typeToString)
            .collect(Collectors.joining(", "));
        return raw + "<" + argStr + ">";
    } else if (type instanceof TypeVariable<?> tv) {
        // e.g., T in List<T> -> "T"
        return tv.getName();
    } else if (type instanceof WildcardType wt) {
        // e.g., ? extends Number -> "? extends java.lang.Number"
        Type[] upper = wt.getUpperBounds();
        Type[] lower = wt.getLowerBounds();
        if (lower.length > 0) return "? super " + typeToString(lower[0]);
        if (upper.length > 0 && !upper[0].equals(Object.class))
            return "? extends " + typeToString(upper[0]);
        return "?";
    } else if (type instanceof GenericArrayType gat) {
        return typeToString(gat.getGenericComponentType()) + "[]";
    }
    return type.getTypeName();
}
```

This recovery is best-effort. Some JARs are compiled with `-g:none` (no debug info) or use ProGuard/R8 obfuscation, which strips the `Signature` attribute. When generic info is absent, `getGenericParameterTypes()` returns the same as `getParameterTypes()` (erased types). ReflectTool detects this by checking whether `getGenericParameterTypes()[i]` is a `Class<?>` (erased) or a `ParameterizedType` (generic info available).

## getDeclaredFields

```java
public static List<FieldInfo> extractFields(Class<?> clazz) {
    List<FieldInfo> fields = new ArrayList<>();
    for (Field f : clazz.getDeclaredFields()) {
        int mod = f.getModifiers();
        if (!Modifier.isPublic(mod) && !Modifier.isProtected(mod)) continue;
        if (f.isSynthetic()) continue;
        fields.add(new FieldInfo(
            f.getName(),
            modifiersToList(mod),
            typeToString(f.getGenericType()),
            hasAnnotation(f, "java.lang.Deprecated")
        ));
    }
    return fields;
}
```

Static final fields (constants) are particularly important for enum-like classes and configuration constants (e.g., `HttpStatus.OK`, `StandardCharsets.UTF_8`). ReflectTool records whether a field is `static`, `final`, `volatile`, or `transient` in the `modifiers` list.

## getDeclaredConstructors

```java
public static List<ConstructorInfo> extractConstructors(Class<?> clazz) {
    List<ConstructorInfo> ctors = new ArrayList<>();
    for (Constructor<?> c : clazz.getDeclaredConstructors()) {
        if (!Modifier.isPublic(c.getModifiers())) continue;
        ctors.add(new ConstructorInfo(
            buildParameterInfos(c.getParameters(), c.getGenericParameterTypes()),
            exceptionsToList(c.getExceptionTypes())
        ));
    }
    return ctors;
}
```

## Interface hierarchy walking

For each class, ReflectTool walks the interface hierarchy:

```java
public static List<String> extractInterfaces(Class<?> clazz) {
    List<String> result = new ArrayList<>();
    // Direct interfaces
    for (Class<?> iface : clazz.getInterfaces()) {
        result.add(iface.getName());
    }
    // Superclass interfaces (recursive)
    Class<?> superclass = clazz.getSuperclass();
    if (superclass != null && !superclass.equals(Object.class)) {
        result.addAll(extractInterfaces(superclass));
    }
    return result;
}
```

This is used by the type-mapping pass to determine whether a class implements `java.util.List` (which maps to `list<T>`), `java.util.Map` (which maps to `map<K,V>`), `java.util.Set`, `java.lang.Iterable`, `java.util.concurrent.Future`, or `java.util.concurrent.CompletionStage` (which maps to `async T`).

## Inner class handling

Inner classes are handled by scanning the `getDeclaredClasses()` of each top-level class:

```java
public static List<ClassInfo> extractInnerClasses(Class<?> clazz, URLClassLoader loader) {
    List<ClassInfo> result = new ArrayList<>();
    for (Class<?> inner : clazz.getDeclaredClasses()) {
        if (!Modifier.isPublic(inner.getModifiers())) continue;
        result.add(buildClassInfo(inner, loader));
    }
    return result;
}
```

Inner class names in the JSON use the `OuterClass$InnerClass` bytecode convention (e.g., `com.google.common.collect.ImmutableMap$Builder`). The type-mapping pass converts this to a Mochi type `guava_ImmutableMap_Builder`.

## module-info.class and JPMS

Java 9 introduced the Java Platform Module System (JPMS). JARs compiled as JPMS modules contain a `module-info.class` file that declares which packages are exported (accessible from outside the module) and which are encapsulated (accessible only within the module).

ReflectTool reads the module descriptor when present:

```java
public static ModuleInfo extractModuleInfo(JarFile jar) throws IOException {
    JarEntry moduleInfo = jar.getJarEntry("module-info.class");
    if (moduleInfo == null) return null;
    // Use ModuleDescriptor.read() to parse the module-info.class bytecode
    try (InputStream is = jar.getInputStream(moduleInfo)) {
        ModuleDescriptor descriptor = ModuleDescriptor.read(is);
        Set<String> exportedPackages = descriptor.exports().stream()
            .filter(e -> e.targets().isEmpty()) // unconditional exports
            .map(ModuleDescriptor.Exports::source)
            .collect(Collectors.toSet());
        return new ModuleInfo(descriptor.name(), exportedPackages, descriptor.version().map(Object::toString).orElse(null));
    }
}
```

When a module descriptor is present, ReflectTool only includes classes from exported packages. Classes in encapsulated packages (e.g., `com.sun.internal.*`, `jdk.internal.*`) are excluded even if they happen to be public.

For automatic modules (JARs without `module-info.class` on a module path), all packages are considered exported. ReflectTool's default behaviour (treating all public classes as accessible) matches the automatic module convention.

## Annotation extraction

ReflectTool extracts annotations relevant to the type-mapping pass:

- `@Deprecated`: flags the item for a SkipReport warning (not an error; deprecated items are still exposed).
- `@SafeVarargs`: indicates the method uses varargs safely; the bridge treats varargs as `list<T>`.
- `@Nullable` / `@NonNull` (from JSR-305, JetBrains, or AndroidX): informs the type-mapping pass whether a return type can be null (affecting `T` vs `T|nil` mapping for reference types).
- `@FunctionalInterface`: flags interfaces that have a single abstract method and can be mapped to Mochi function types.

## Go-side parsing

The Go side (`package3/java/reflect/surface.go`) defines:

```go
type Surface struct {
    ReflectToolVersion string      `json:"reflect_tool_version"`
    JavaVersion        string      `json:"java_version"`
    JarPath            string      `json:"jar_path"`
    ModuleInfo         *ModuleInfo `json:"module_info"`
    LoadErrors         []LoadError `json:"load_errors"`
    Classes            []ClassInfo `json:"classes"`
}

type ClassInfo struct {
    Name           string          `json:"name"`
    Kind           string          `json:"kind"` // "class", "interface", "enum", "annotation", "record"
    Modifiers      []string        `json:"modifiers"`
    Superclass     string          `json:"superclass"`
    Interfaces     []string        `json:"interfaces"`
    TypeParameters []TypeParam     `json:"type_parameters"`
    Annotations    []string        `json:"annotations"`
    Deprecated     bool            `json:"deprecated"`
    InnerClasses   []InnerClassRef `json:"inner_classes"`
    Constructors   []ConstructorInfo `json:"constructors"`
    Methods        []MethodInfo    `json:"methods"`
    Fields         []FieldInfo     `json:"fields"`
}
```

The parsing step uses `encoding/json`. After parsing, the Go side passes `Surface` to `typemap.Translate(surface)` which produces a `TranslatedSurface` containing only the items the closed type table could map, plus a `SkipReport` listing every item that was skipped with its reason.

## Performance

ReflectTool on the 24-package fixture corpus (all 24 JARs plus their transitive dependencies, approximately 150 JARs total):

- JVM startup: ~200ms (one-time cost for the subprocess; the JVM for ReflectTool is separate from the embedded JVM).
- Class enumeration and reflection: ~2-8 seconds depending on the JAR size (guava has ~200 public classes; spring-core has ~400; netty-all has ~800).
- JSON serialisation to stdout: ~10-50ms.
- Go-side JSON parsing: ~5-20ms.

Total per-JAR time (after JVM startup): 2-10 seconds. For 24 JARs: 50-240 seconds on a cold run. JARs are cached by SHA-256; subsequent `mochi pkg lock` invocations skip JARs whose `reflection-json-sha256` already matches in `mochi.lock`.
