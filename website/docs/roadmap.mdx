This page describes where Mochi is going. It is directional and changes
with feedback from people using the language. Filed issues and
discussions on GitHub get read before sprint planning.

The categories below mirror how we work internally: the language and
its compiler, the toolchain you run, the transpiler exits to other
ecosystems, and the platforms we target.

:::note Status legend
Done means it has shipped to a release that you can install today.
In progress means there is a working branch or open PR.
Planned means we have committed to building it; the design might still
shift.
Considering means we like the idea but have not committed yet.
:::

## v0.16.0 (current release)

v0.16.0 shipped in May 2026. It is the largest Mochi release to date:
605 commits, 243 merged PRs, and +262,082 lines of new code across
4,642 files. Seven MEPs are marked Final in this release.

**New compile targets (all Final):**

```sh
mochi build --target=swift-macos        # MEP-49 — Swift, macOS 15+
mochi build --target=swift-ios          # MEP-49 — iOS 18+ app bundle
mochi build --target=swift-static-linux # MEP-49 — musl single-file binary
mochi build --target=php                # MEP-55 — PHP 8.3+
mochi build --target=ruby               # MEP-56 — CRuby 3.3+ / TruffleRuby
mochi build --target=rust               # MEP-53 — Rust 1.78+ (phases 0-6)
mochi build --target=typescript         # MEP-52 — Node 22 / Deno 2 / Bun 1 (phases 2-6)
mochi build --target=go                 # MEP-54 — Go 1.26 (phases 2-6)
```

**Completed package bridges (all Final):**

```sh
import python "numpy"                           # MEP-71 — PyPI, 18 phases
import kotlin "io.ktor:ktor-client-core:3.0.0"  # MEP-70 — Maven Central, 14 phases

import go "github.com/gin-gonic/gin"            # MEP-74 — GOPROXY, 18 phases

```

**Also in v0.16.0:** MEP-50 (Kotlin transpiler, all 18 phases), MEP-51
(Python transpiler, all 18 phases), Java bridge phases 0-15 (MEP-67),
.NET NuGet bridge phases 0-13 (MEP-68), PHP bridge phases 0-14 (MEP-75),
Rust bridge phases 8-13 (MEP-73), and specs for the Swift bridge
(MEP-69) and TypeScript/JS bridge (MEP-72).

See the [v0.16.0 release notes](/docs/releases/v0.16.0) for the full

## v0.13.0 (May 2026)

v0.13.0 completed the BEAM/Erlang transpiler under
[MEP-46](/docs/mep/mep-0046).

### Language core

- Done. Bytecode VM with constant folding, inline caches, and
  liveness-based dead-code elimination. Hot scripts start in
  single-digit milliseconds after the first run.
- Done. Static type inference across function calls, generic
  instantiations, and `match` arms.
- Done. `let` and `var` bindings with the immutable-by-default rule.
- Done. Functions, closures, and arrow lambdas. Closures capture by
  reference and are first-class values.
- Done. `type` for structs with inline methods. Field access uses the
  dot operator; field assignment requires `var`.
- Done. Union types with exhaustiveness checking on `match`.
- Done. `for`, `while`, `if`/`else`, `match`, `break`, `continue`,
  range expressions.
- Done. Built-in collections: `list<T>`, `map<K,V>`, `set<T>`,
  `omap<K,V>` with the full prelude method set.
- Done. Packages and imports.
- Done. Built-in test blocks with `expect` assertions.
- Done. Agents and streams: `agent`, `stream`, `emit`, `on Event`,
  `intent`.
- Done. `generate text {}`, `generate embedding {}`, and
  `generate <Provider> {}`. Tool calling, structured output, streaming
  responses, and cassette playback.
- Done. Dataset queries with `sort by`, `take`, `group by`, `join`.
- Done. Datalog with bottom-up semi-naïve evaluation.
- Done. `async`/`await`.
- Done. `fetch "<url>" into <var>` and `json_decode`.
- Done. FFI through `extern` declarations.
- Done. Pipe operator and partial application.
- In progress. Language server (LSP). Diagnostics, hover types, and
  goto-definition are working on the LSP branch.
- Planned. `mochi fmt` formatter.
- Planned. Generics type bounds (`<T: Comparable>`), error propagation
  operator (`?`), and interface / protocol declarations.

## v0.17.0 (next release)

v0.17.0 will focus on completing the in-progress transpiler targets and
advancing the open package bridges to Final status.

**Primary goals:**

1. **TypeScript/JS transpiler Final (MEP-52 phases 7-18).** Agents,
   streams, async/await, Datalog, file I/O, LLM cassette, fetch, npm
   packaging, and reproducible builds. The three-runtime gate (Node 22 /
   Deno 2 / Bun 1) continues for every new phase.

2. **Rust transpiler Final (MEP-53 phases 7-18).** Closures and
   higher-order functions (heap closures via `Box<dyn Fn>`), agents via
   `Arc<Mutex<T>>`, streams via `tokio::sync::broadcast`, async/await,
   Datalog, file I/O, LLM cassette, HTTP fetch, `cargo publish`
   packaging, and reproducible builds.

3. **Go transpiler Final (MEP-54 phases 7-18).** Closures, agents via
   goroutine + channel, streams, async/await, Datalog, file I/O, LLM,
   fetch, and `go mod` packaging.

4. **Java package bridge Final (MEP-67 phases 16+).** Complete the
   remaining phases: full async bridge for `CompletableFuture` chains,
   JNI type-erasure edge cases, sealed class / record bridging.

5. **PHP package bridge Final (MEP-75 phases 15+).** Close out the
   remaining corpus validation phases and any deferred async edge cases.

6. **Rust crates.io bridge Final (MEP-73 phases 14+).** Close out the
   remaining phases including the full embedded/no_std validation corpus.

7. **Swift package bridge implementation start (MEP-69).** The spec and
   research bundle landed in v0.16.0. Implementation phases 0-6 are
   the target for v0.17.0.

8. **TypeScript/JS bridge implementation start (MEP-72).** The spec
   landed in v0.16.0. Implementation phases 0-6 are the target for
   v0.17.0.

9. **LSP milestone.** Diagnostics, hover types, goto-definition, and
   auto-completion complete enough to ship as the default `mochi lsp`
   subcommand.

## v1.0 (stable language)

The 1.0 milestone marks the language as stable. After 1.0, the core
syntax and semantics will not change in a backwards-incompatible way
without a `--edition` opt-in.

To get there, Mochi needs:

- A versioned language specification document.
- Generics type bounds (`<T: Comparable>`), the error propagation
  operator (`?`), and interface / protocol declarations shipped and used
  in the standard library.
- A stable standard library API: `io`, `fs`, `time`, `http`, `crypto`,
  `json`. Not breaking these later is most of the work.
- A package registry with semantic-version resolution, lockfiles, and
  a publish workflow. (The `mochi.lock` infrastructure that shipped in
  v0.16.0 is the foundation.)
- LSP feature-complete enough that VS Code and JetBrains feel like a
  first-class IDE experience.
- Native Windows support without WSL.
- All current in-progress transpilers (TypeScript, Rust, Go) reaching
  Final status.
- A test suite that exercises every spec example on every supported
  platform and every transpiler target.

We are not promising a date. We are promising that 1.0 ships when the
list above is true and not before.

## Things we are deliberately not building

To stay small, some doors stay closed:

- Operator overloading. `+` on `string` and `list` is the only overload
  and it is in the language definition; users cannot overload operators
  on their own types.
- Macros. Code that generates code adds an extra debugging layer for a
  payoff that templates and codegen tools handle well enough.
- Inheritance. Composition through structs and methods covers modeling;
  interfaces (when they ship) cover polymorphism.
- A template engine, web framework, or ORM in the standard library.
  These belong in third-party packages.

## How to influence priorities

- Open a [GitHub Discussion](https://github.com/mochilang/mochi/discussions)
  with the use case. Real programs help us pick the right design more
  than abstract requests.
- File a bug with a reproduction. Bug reports get priority over feature
  work.
- Ship a patch. The contributor guide is in the repo; small PRs that
  add tests for missing behavior are easiest to land.
